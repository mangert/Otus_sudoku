# Политика тестирования

- Каждое изменение поведения сопровождай тестом, который падает без изменения и проходит после него.
- Используй существующие легковесные проверки из `tests/test_utils.h`; внешний тестовый фреймворк без согласования не добавляй.
- Размещай тесты DLX в `tests/dancing_links/`, а тесты решателя — в `tests/sudoku/`.
- Именуй тестовые функции по шаблону `test_<behavior>` и регистрируй новые тестовые исполняемые файлы в `tests/CMakeLists.txt`.
- Проверяй успешные сценарии, граничные значения, некорректный ввод и отсутствие решения, если эти случаи относятся к изменению.

Основная локальная проверка:

```powershell
cmake --preset x64-debug
cmake --build out/build/x64-debug
ctest --test-dir out/build/x64-debug --output-on-failure
```

В отчёте о работе указывай выполненные команды и результат тестов. Если тесты запустить нельзя, явно объясни причину.
