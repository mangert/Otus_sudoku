# План реализации JSON-ввода и вывода судоку

## 1. Формализованное описание задачи

Расширить консольное приложение `SudokuApp` поддержкой загрузки исходного судоку из JSON-файла и сохранения решённой доски в JSON-файл. Существующие способы — TXT-файл и клавиатура — сохранить без изменения. JSON реализовать без внешних зависимостей через строгий ручной парсер стандартными средствами C++23. Публичный API решателя в `include/sudoku/` не изменять.

Критерии готовности:

- приложение явно предлагает загрузку и сохранение в TXT или JSON;
- поддерживаются размеры 4×4, 9×9 и 16×16;
- некорректный JSON обрабатывается без исключений и аварийного завершения;
- JSON-запись повторно читается приложением без потери данных;
- новая функциональность покрыта автоматическими тестами и документацией.

## 2. Зафиксировать JSON-контракт

Использовать единый формат для исходных и решённых досок:

```json
{
  "size": 4,
  "board": [
    [1, 0, 0, 4],
    [0, 4, 1, 0],
    [0, 1, 4, 0],
    [4, 0, 0, 1]
  ]
}
```

Правила формата:

- корень — объект ровно с полями `size` и `board`;
- порядок полей произвольный, повторные и неизвестные поля запрещены;
- `size` — положительное целое число, совпадающее с размером, ранее выбранным в меню;
- `board` содержит ровно `N` массивов по `N` целых чисел;
- допустимые значения клеток — от `0` до `N`, где `0` означает пустую клетку;
- разрешены стандартные JSON-пробелы, переводы строк и табуляция;
- комментарии, trailing comma, дробные числа, экспоненты, экранированные имена полей и данные после корневого объекта запрещены.

## 3. Реализовать JSON I/O без зависимостей

Добавить в слой `app` отдельный header-only модуль JSON-ввода/вывода, не смешивая парсер с решателем.

Внутренний курсорный парсер должен:

- прочитать файл через `std::ifstream` в `std::string`;
- последовательно распознавать `{}`, `[]`, `:`, `,`, имена полей и целые числа;
- пропускать только допустимые JSON-пробелы;
- разбирать числа через `std::from_chars`;
- контролировать границы строки перед каждым чтением;
- проверять наличие, уникальность и структуру полей;
- требовать конец входных данных после закрывающей скобки.

Добавить интерфейс приложения:

- `readBoardFromJsonFile<N>()`, возвращающий `std::expected<Board, JsonIoError>`;
- `writeBoardToJsonFile<N>()`, возвращающий `std::expected<void, JsonIoError>`;
- `JsonIoError` с состояниями открытия файла, синтаксиса, схемы, несовпадения размера, формы доски, значения клетки и ошибки записи.

Парсер и сериализатор не должны использовать `throw`. Сериализатор выводит форматированный JSON, поля в порядке `size`, затем `board`, и завершающий перевод строки. Существующий файл при сохранении перезаписывается, как и при текущем TXT-сохранении.

## 4. Дополнить консольный интерфейс

Изменить меню источника данных:

1. «Загрузить из TXT-файла»;
2. «Загрузить из JSON-файла»;
3. «Ввести с клавиатуры».

Изменить меню после решения:

1. «Сохранить в TXT-файл»;
2. «Сохранить в JSON-файл»;
3. «Решить другую».

Для JSON:

- использовать явно выбранный обработчик, не определять формат по расширению;
- не добавлять расширение к имени автоматически;
- при несовпадении `size` сообщать ожидаемый и фактический размеры;
- преобразовывать остальные `JsonIoError` в краткие русскоязычные сообщения;
- после ошибки загрузки возвращаться к выбору источника;
- сохранить текущий жизненный цикл приложения после сохранения или отказа от него.

- Не добавлять `FetchContent`, пакетные менеджеры или сторонние библиотеки.
- Создать отдельную тестовую цель `test_sudoku_json_io` и зарегистрировать её в CTest как `SudokuJsonIoTests`.
- Подключить к тесту каталог `app/` и существующий `tests/test_utils.h`.

## 6. Добавить автоматические тесты

Покрыть следующие сценарии:

1. чтение корректной доски 4×4;
2. чтение JSON с другим порядком полей и допустимыми пробелами;
3. сохранение и повторное чтение решённой доски 9×9;
4. работа шаблонного кода с доской 16×16;
5. отсутствующий или недоступный файл;
6. повреждённый JSON, trailing comma и лишние данные после объекта;
7. отсутствующее, повторное или неизвестное поле;
8. несовпадение `size` с выбранным размером;
9. неверное число строк или клеток в строке;
10. строка, дробное число либо значение вне диапазона `0..N`;
11. ошибка сохранения в несуществующий каталог.

Временные файлы создавать в системном временном каталоге и удалять через RAII. Существующие тесты TXT, решателя и DLX не изменять без необходимости.


Дополнительно вручную проверить сценарий:

1. выбрать размер 9×9;
2. загрузить `easy9.json`;
3. решить доску;
4. сохранить результат в новый JSON;
5. повторно загрузить сохранённый файл и убедиться, что доска корректно читается.

## 9. Принятые ограничения

- JSON не определяет размер автоматически: пользователь сначала выбирает 4, 9 или 16.
- Поддерживается только описанный профиль JSON, а не произвольные JSON-документы.
- Расширение файла не проверяется и не изменяется.
- Форматы TXT и клавиатурного ввода сохраняют текущее поведение.
- Алгоритм DLX и публичный API `SudokuSolver<N>` остаются без изменений.
- Несвязанные изменения в рабочем дереве не затрагиваются.
