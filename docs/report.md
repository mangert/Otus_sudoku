# Реализация алгоритма Dancing Links (DLX) для решения задачи точного покрытия на примере судоку

## 1. Постановка задачи

Целью данной работы является реализация алгоритма Dancing Links (DLX), предложенного Дональдом Кнутом, для эффективного решения задачи точного покрытия (Exact Cover) на примере судоку.

Судоку — это головоломка, в которой требуется заполнить сетку `N × N` (обычно 9×9) цифрами от 1 до N так, чтобы в каждой строке, каждом столбце и каждом блоке `√N × √N` каждая цифра встречалась ровно один раз. В рамках проекта реализован решатель для размерностей 4×4, 9×9 и 16×16.

## 2. Теоретическая база

### 2.1 Задача точного покрытия (Exact Cover)

Задача точного покрытия формулируется следующим образом: дана матрица, состоящая из 0 и 1. Требуется найти набор строк, содержащих ровно одну единицу в каждом столбце . Судоку естественным образом сводится к этой задаче :

| Тип ограничения | Количество | Описание |
|-----------------|------------|----------|
| Клетки | N² | Каждая клетка должна содержать ровно одну цифру |
| Строки | N² | В каждой строке каждая цифра встречается ровно один раз |
| Столбцы | N² | В каждом столбце каждая цифра встречается ровно один раз |
| Блоки | N² | В каждом блоке каждая цифра встречается ровно один раз |

Для судоку 9×9 это даёт матрицу размером **729 × 324**.

### 2.2 Алгоритм X и Dancing Links

Алгоритм X — это простой рекурсивный метод перебора с возвратом (backtracking) для решения задачи точного покрытия . Его суть:

1. Если матрица пуста — решение найдено.
2. Выбрать столбец с наименьшим количеством единиц.
3. Перебрать строки, содержащие единицу в этом столбце.
4. Для каждой такой строки включить её в решение и удалить все конфликтующие строки и столбцы.
5. Рекурсивно повторить.

**Dancing Links** — это эффективная реализация алгоритма X . Ключевая идея заключается в том, что удаление и последующее восстановление узла из двусвязного списка может быть выполнено за O(1) с помощью двух пар операций :

```cpp
// Удаление узла
col->right->left = col->left;
col->left->right = col->right;

// Восстановление узла
col->right->left = col;
col->left->right = col;
```

Эта техника получила название «танцующие ссылки» (dancing links), поскольку указатели «танцуют», переставляясь при удалении и восстановлении .

## 3. Реализация матрицы Dancing Links

### 3.1 Структура узла

```cpp
struct Node {
    Node *left, *right, *up, *down;  // 4 указателя для двусвязных списков
    Node *column;                     // указатель на заголовок столбца
    int size;                         // только для заголовков: количество единиц
    int id;                           // идентификатор строки или столбца
};
```

**Особенности:**
- Все узлы: и узлы матрицы, и узлы заголовка — имеют одинаковую структуру, что соответствует классической реализации Кнута.
- 4 указателя для перемещения по горизонтальным и вертикальным спискам.
- Дополнительный указатель `column` позволяет быстро определить, к какому столбцу принадлежит узел, без подъёма по вертикальным ссылкам.
- Для заголовков столбцов используется `size` — это основа эвристики выбора столбца с минимальным количеством единиц .
- Для хранения строки заголовков дополнительно используется std::vector. Это компромиссное решение, направленное на ускорение доступа к столбцу по индексу и безопасность при операциях cover/uncover.

### 3.2 Ключевые операции

- `cover(col)` — удаляет столбец и все строки, содержащие единицу в этом столбце.
- `uncover(col)` — восстанавливает удалённое в обратном порядке.
- Для контроля порядка вызовов используется стек, обеспечивающий принцип LIFO (Last In — First Out) при откате.

### 3.3 Управление памятью

 - Матрица не поддерживает копирование (конструктор копирования и оператор присваивания удалены). Это сделано намеренно, поскольку при копировании нарушилась бы сложная система перекрёстных ссылок между узлами. Для передачи владения используется move-семантика.
 - Для построения матрицы используются "сырые указатели". Использование smart pointers повлекло бы дополнительные сложности, связанные с вопросами владения при циклических ссылках и снижение производительности. Так как никто снаружи не получает доступ к узлам напрямую, а уничтожение осуществляется деструктором класса, использование "сырых" указателей безопасно.

## 4. Реализация решателя судоку

### 4.1 Шаблонный класс

Класс `SudokuSolver` реализован как шаблонный с параметром `N` (размер стороны судоку). Это позволяет:
- Использовать один и тот же код для 4×4, 9×9 и 16×16.
- Вычислять константы (`BLOCK_SIZE`, `CELLS`, `TOTAL_COLUMNS`) на этапе компиляции.
- Использовать `std::array` фиксированного размера для хранения доски.

### 4.2 Концепт ValidSudokuSize

Шаблонный параметр ограничен концептом, проверяющим, что N является полным квадратом (4, 9, 16...). При попытке инстанцировать класс для недопустимого размера компилятор выдаст понятную ошибку.

### 4.3 Построение матрицы точного покрытия

Для каждой тройки `(row, col, digit)` вычисляются 4 индекса столбцов — по одному для каждой группы ограничений: 

```cpp
int cell_idx = row * N + col;                     // клетка
int row_idx = CELLS + row * N + d;                // строка + цифра
int col_idx = 2 * CELLS + col * N + d;            // столбец + цифра
int block_idx = 3 * CELLS + block * N + d;        // блок + цифра
```
В итоге получается разреженная матрица, в каждой строке которой ровно 4 действительных узла.

### 4.4 Особенности и ограничения

- Класс может принимать исходные данные как в виде полной доски, так и в виде вектора кортежей {строка, столбец, цифра}.
- Решатель находит первое корректное решение судоку, если оно существует. Поиск всех решений, с учетом того, что для отдельных случаев их количество может быть огромно,  - отдельная задача, не вошедшее в данную реализацию
- Количество ограничений (4) задано константой времени компиляции, так как класс решателя использует для передачи набора ограничений каждой клетки поля в DLX-матрицу std::array. Это накладывает ограничение на возможность изменения количества ограничений (например, для решения модифицированных судоку с диагоналями). Использование std::vector на этапе проектирования рассматривалось, но было отвергнуто как неэффективное (Для 729 строк × 4 = 2916 вызовов. Если каждый вызов аллоцирует вектор в куче — это огромные накладные расходы.)


### 4.4 Обработка начальных условий

Фиксированные клетки принудительно «покрываются» перед началом поиска. При обнаружении конфликта (например, две разные цифры в одной клетке) возвращается ошибка `INVALID_CONSTRAINTS`.

## 5. Консольное приложение

Приложение предоставляет следующие возможности:
- Выбор размера судоку (4, 9 или 16).
- Загрузка из текстового файла.
- Ввод с клавиатуры.
- Сохранение решения в файл.
- Вывод доски с разделителями блоков.

## 6. Тестирование и результаты

### 6.1 Тестовые наборы

| Тест | Описание |
|------|----------|
| 4×4 (easy) | Простое судоку 4×4 |
| 9×9 (easy) | Классическое лёгкое судоку |
| 9×9 (easy, через список клеток) | Инициализация списком фиксированных клеток |
| 9×9 (medium) | Судоку средней сложности |
| 9×9 (Al Escargot) | Одно из самых сложных судоку для человека |
| 16×16 | Судоку 16×16 с 68 подсказками |
| No solution | Заведомо нерешаемое судоку |
| Invalid | Противоречивые начальные данные |

### 6.2 Производительность (Release-сборка)

| Тест | Время (мкс) | Время (мс) |
|------|-------------|------------|
| Easy 4×4 | 80 | 0.08 |
| Easy 9×9 | 700 | 0.70 |
| Easy 9×9 (список клеток) | 607 | 0.61 |
| Medium 9×9 | 615 | 0.62 |
| Al Escargot 9×9 | 693 | 0.69 |
| Sudoku 16×16 | 9 369 | 9.37 |

- 4×4 решается практически мгновенно (0.08 мс).

- 9×9 независимо от сложности решается за 0.6–0.7 мс — эвристика выбора столбца с минимальным размером нивелирует «сложность» для человека.

- 16×16 требует уже ~9.4 мс, что ожидаемо, так как матрица в 256 раз больше 4×4 и в ~3.16 раза больше 9×9.

### 6.3 Сравнение с другими реализациями

Согласно открытым данным, реализации DLX на C++ решают 9×9 судоку в среднем за **0.85–1.2 мс** . Наше время порядка 0.6–0.8 мс (600–800 мкс) находится в том же диапазоне, что подтверждает эффективность реализации.

## 7. Выводы

В ходе работы была реализована структура Dancing Links для эффективного решения задачи точного покрытия. На её основе разработан решатель судоку, поддерживающий размеры 4×4, 9×9 и 16×16.

**Основные результаты:**
- DLX демонстрирует высокую производительность (0.6–0.8 мс для 9×9).
- Шаблонная реализация позволяет легко масштабировать код на разные размеры.
- Концепт ValidSudokuSize обеспечивает безопасность на этапе компиляции.
- Решение успешно протестировано на различных наборах данных, включая сложное судоку Al Escargot.

**Перспективы развития:**
- Поддержка судоку других типов (диагональные, «фигурные» блоки).
- Поиск всех решений для головоломок с неоднозначным ответом.
