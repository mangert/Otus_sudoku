## 1. Реализация алгоритма

### 1.1. Основная идея

Судоку сводится к **задаче точного покрытия (Exact Cover)**. Каждая клетка, строка, столбец и блок — это ограничение (столбец матрицы). Каждый возможный вариант «поставить цифру X в клетку (r,c)» — это строка матрицы, покрывающая ровно 4 ограничения (клетка, строка, столбец, блок). Все четыре группы необходимы — без любой из них возможны невалидные решения.

Матрица получается размера **N³ × 4N²**. Для классического судоку 9×9 это **729 × 324**. Матрица очень разреженная (в каждой строке ровно 4 единицы), поэтому хранение в виде двумерного массива невозможно. Вместо этого используется структура Dancing Links.

### 1.2. Структура данных Dancing Links (DLX)

Реализовать класс `DancingLinksMatrix`, внутри которого:

- **Узел (struct Node)**:
  - указатели `left`, `right`, `up`, `down`
  - указатель `column` на «голову» столбца (для обычных узлов) или на себя (для заголовков)
  - для узлов-заголовков столбцов: `size` (количество единиц в столбце), `id` (индекс ограничения)
  - для обычных узлов: `id` (идентификатор строки)

- **Горизонтальный циклический список всех заголовков столбцов** (для перебора столбцов и выбора минимального по `size`).

- **Вертикальные циклические списки** внутри каждого столбца (включая сам узел-заголовок).

**Ключевые операции:**

- `cover(ColumnNode* col)` — удаляет столбец из горизонтального списка заголовков и все строки, в которых есть единица в этом столбце, из других столбцов. Это «запрещает» варианты, конфликтующие с выбранным. Работает за счёт перестановки указателей, без копирования данных.
- `uncover(ColumnNode* col)` — восстанавливает удалённое, выполняя действия в строго обратном порядке. Благодаря циклическим спискам и сохранению указателей, восстановление делается без дополнительной памяти.

**Дополнительные операции:**
- `addRow()` — добавление строки в матрицу (вертикальная вставка в каждый указанный столбец, горизонтальная связка узлов строки).
- `chooseColumn()` — выбор столбца с минимальным `size` (эвристика для ускорения).
- `isCovered()` — проверка, покрыт ли столбец (по положению в горизонтальном списке).

**Поиск решения (рекурсивный):**

1. Если все столбцы удалены (`root->right == root`) — решение найдено.
2. Выбрать столбец с **минимальным `size`** (эвристика, резко ускоряет перебор).
3. Покрыть выбранный столбец.
4. Перебрать все строки в этом столбце (по `down`):
   - Выбрать эту строку (запомнить её `row_id`)
   - `cover` для всех столбцов, в которых есть единицы в этой строке
   - Рекурсивный вызов
   - Если решение найдено — вернуть успех
   - Иначе `uncover` для всех тех же столбцов (откат) и попробовать следующую строку
5. Раскрыть выбранный столбец и вернуть `false` (нет решения).

### 1.3. Класс судоку (`SudokuSolver`)

- **Построение матрицы** (один раз при инициализации):
  - Создать `4 × N²` столбцов (4 группы ограничений: клетки, строки, столбцы, блоки).
  - Сгенерировать `N³` строк — по одной на каждую тройку `(row, col, digit)`.
  - Для каждой строки вычислить 4 индекса столбцов (через `getColumnIndices`) и добавить строку в матрицу DLX через `addRow`.

- **Учёт начальных условий**:
  - Для каждой фиксированной клетки из `fixed_cells` принудительно покрыть все 4 столбца соответствующей строки через `cover`. Если во время покрытия обнаруживается конфликт (столбец уже покрыт) — возвращается ошибка `INVALID_CONSTRAINTS`.

- **Запуск решения**:
  - Вызвать `search` на подготовленной матрице.
  - Если решение найдено — преобразовать список `row_id` обратно в доску через `decodeRowId` и объединить с начальными значениями.
  - Если нет — вернуть ошибку `NO_SOLUTION`.

## 2. Тестирование

### 2.1. Проверка корректности (точность)

Для решённой доски **обязательно** проверить через функцию `is_valid_sudoku()`:
- Все цифры в диапазоне 1..N (или 0 для пустых)
- В каждой строке, каждом столбце и каждом блоке нет повторяющихся цифр

Для **нерешаемых** судоку:
- Тест с противоречивыми начальными данными (две одинаковые цифры в одной строке) — ожидается `INVALID_CONSTRAINTS`
- Тест с заведомо нерешаемой головоломкой — ожидается `NO_SOLUTION`

### 2.2. Производительность

Выполнить замеры времени решения:
- **4×4**
- **9×9 (легкое)**
- **9×9 (Al Escargot)**

**Тестовые наборы:**
- Простые судоку 4×4 и 9×9
- Сложное судоку *Al Escargot*
- Судоку 16×16 (с использованием буквенных обозначений A–F)


### 2.3. На что сделать упор

**Приоритет 1 — корректность.** Решение всегда правильно, если оно существует.

**Приоритет 2 — производительность** за счёт:
- Эвристики выбора столбца с минимальным размером.
- Хранения разреженной матрицы через списки (без копирования данных).
- Отсутствия динамических аллокаций во время поиска.

**Приоритет 3 — расширяемость и удобство использования:**
- Поддержка разных размеров (4×4, 9×9, 16×25) через шаблонный параметр.
- Консольное приложение с загрузкой из файла и вводом с клавиатуры.
- Сохранение решения в файл.
