# Отчёт о работе с Codex

## 1. Описание условий

Работа выполнена с помощью Codex — программного агента OpenAI на базе модели GPT-5.

Основные инструкции проекта находятся в файле [AGENTS.md](../AGENTS.md). В работе также использовались следующие правила:

- [Руководство по стилю](../.codex/rules/style_guide.md);
- [Политика тестирования](../.codex/rules/testing_policy.md);
- [Архитектурные решения](../.codex/rules/architecture_decisions.md);
- [Правила логирования](../.codex/rules/logging.md);
- [Правила обработки ошибок](../.codex/rules/error_handling.md).

## 2. Исходный проект

Исходный проект реализовывал решение судоку через сведение задачи к точному покрытию и применение алгоритма Dancing Links. Header-only решатель `SudokuSolver<N>` поддерживал размеры, являющиеся полными квадратами, а консольное приложение работало с досками 4×4, 9×9 и 16×16.

Доску можно было ввести с клавиатуры или загрузить из текстового файла. Решённая доска сохранялась в TXT. Поддержки JSON не было.

## 3. Новый функционал

В приложение добавлены чтение исходных досок из JSON и сохранение решений в JSON без сторонних библиотек. Реализован строгий формат с полями `size` и `board`, проверкой структуры, размера и значений клеток.

Консольный интерфейс позволяет выбирать между TXT, JSON и вводом с клавиатуры, а результат сохранять в TXT или JSON. Ошибки файловых операций, синтаксиса и схемы возвращаются как состояния через `std::expected`.

Для Windows настроены UTF-8-компиляция и кодовая страница консоли, чтобы русский текст отображался корректно.

## 4. Проделанная работа

Работа выполнялась по [плану реализации JSON I/O](json_io_implementation_plan.md). Полная история пользовательских запросов сохранена в [журнале промптов](../.codex/prompts.md).

В ходе работы:

- изучена структура проекта и зафиксированы правила разработки;
- подготовлено краткое [описание проекта](project_overview.md);
- реализованы строгий JSON-парсер и сериализация досок;
- обновлены меню консольного приложения;
- добавлены CMake-цель и автоматические тесты JSON I/O;
- протестированы доски 4×4, 9×9 и 16×16, ошибочные файлы, схема и значения;
- добавлен пример `easy9.json`, эквивалентный `easy9.txt`;
- обновлена пользовательская и проектная документация;
- выполнены полная сборка, все автоматические тесты и ручной сквозной сценарий;
- изменения исходного проекта закоммичены и отправлены в удалённый репозиторий.

## 5. Doxygen-документация

Doxygen-документация перегенерирована с учётом JSON I/O и новых тестов. Обновлённые HTML-файлы опубликованы в отдельном репозитории на github-pages [Otus_sudoku_docs](https://mangert.github.io/Otus_sudoku_docs/index.html).

## 6. Наблюдения и выводы

- Файл AGENTS.md просила сгенерировать сам Codex, указав ему, что там примерно должно быть
- Файлы с правилами писала руками, кроме правил логирования. Правила логирования писала вместе с Codex.
- Для проверки, как Codex следует правилам, решила сделать небольшое изменение - добавить работу с json-файлами
- Чтобы реализовать изменения попросила Codex составить план реализации, дальше шла по по плану
- В процессе работы следила за тем, что Codex делает, в общем, правила он соблюдал. С логированием промптов пришлось немножко подкорректироваться, чтобы он сразу записывал правила в файл в нужном порядке
- Codex смог самостоятельно по запросу запустить "ручной" проход по решателю, он действительно запустил cmd.exe и там прошел, правда, у него не сразу получилось
- Ну в общем проект простой, поэтому сложных инструметов типа скиллов и mcp-серверов не потребоввлось.
- Все промты агент записывал (как я указала в правилах) в файл [prompts.md](../.codex/prompts.md)
